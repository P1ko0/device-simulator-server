# 工业设备模拟服务端

使用 C++17、Qt Core、Qt Network 和 Qt SerialBus 开发的控制台程序，为 Qt 上位机提供文本 TCP 与 Modbus TCP 接口，用于设备控制、状态查询、通信异常处理和客户端联调。

设备由内存中的 Device 状态机模拟，尚未连接真实 PLC、电机或传感器。当前仅处理 1 号设备。

## 配套项目

- 服务端仓库：[device-simulator-server](https://github.com/P1ko0/device-simulator-server)
- 客户端仓库：[industrial-device-monitor](https://github.com/P1ko0/industrial-device-monitor)

服务端负责协议解析、请求校验、设备状态转换及寄存器映射。客户端负责界面、请求发送、回复解析、连接管理和 SQLite 报警存储。

## 已实现功能

- 使用 QTcpServer 接收连接，使用 QTcpSocket 收发 UTF-8 文本消息，并记录连接与断开。
- 按换行符提取完整请求，解析命令、设备编号及参数。
- 校验请求格式、设备编号、参数类型与范围，对错误请求返回错误信息。
- 通过 Device 状态机处理启动、停止、复位和故障模拟，支持查询状态及设置速度。
- 使用 QModbusTcpServer 提供输入寄存器、保持寄存器和启动线圈。
- 文本 TCP 和 Modbus TCP 共享 Device 状态；状态改变后同步输入寄存器地址 2。
- 支持通过启动线圈尝试启动设备，处理后清零线圈。

## 接口地址

| 通道 | 默认地址 | 设备编号 |
|---|---|---|
| 文本 TCP | `127.0.0.1:5000` | 1 |
| Modbus TCP | `127.0.0.1:1502` | 1 |

默认地址用于本机联调。跨机器联调时，需相应修改服务端监听地址和客户端目标地址，并确认端口连通。

## 文本 TCP 协议

编码为 UTF-8。每条请求和回复均以换行符结束，请求固定为三个字段：

```text
命令|设备编号|参数值\n
```

这里的 `\n` 表示实际换行符。无参数命令也保留第三个空字段，例如 `START|1|` 后跟换行符。

| 命令 | 请求内容（末尾均需加换行） | 含义 |
|---|---|---|
| START | `START|1|` | 尝试启动设备 |
| STOP | `STOP|1|` | 尝试停止设备 |
| RESET | `RESET|1|` | 尝试复位设备 |
| FAULT | `FAULT|1|` | 将设备设为 error，用于故障模拟 |
| GET_STATUS | `GET_STATUS|1|` | 查询设备状态 |
| SET_SPEED | `SET_SPEED|1|1800` | 设置速度设定值 |

### 校验规则

- Request 保存解析后的命令、设备编号和参数文字。
- parseRequest() 检查字段数量、非空命令及正整数设备编号。
- 当前仅接受设备编号 1。
- SET_SPEED 参数必须为 0～3000 的整数。
- 其他已支持命令的参数必须为空。
- 非法状态转换、未知命令和非法参数均返回错误信息；错误请求不会中止后续请求处理。

回复示例：

```text
OK|running
STATE|stopped
OK|1800
ERR|UNKNOWN_COMMAND|idle
```

状态操作成功返回设备状态；速度设置成功返回设定值。客户端需结合请求类型解释回复，不能将所有 `OK` 后的内容都当作设备状态。各错误码的准确拼写以当前处理代码为准。

## 设备状态

| 操作 | 允许的原状态 | 操作后状态 |
|---|---|---|
| START | idle | running |
| STOP | running | stopped |
| RESET | stopped、error | idle |
| FAULT | 故障模拟入口 | error |

GET_STATUS 只查询状态。SET_SPEED 修改设定值，不代表模拟实际速度会跟随变化。

客户端断开或重启不会重置仍在运行的服务端设备。服务端进程重启后，设备状态恢复为 idle。

## Modbus TCP 映射

以下地址均为代码使用的零起始地址。

| 区域 | 地址 | 含义 | 当前实现 |
|---|---|---|---|
| Coils | 0 | 启动命令 | 写入 1 后尝试 device.start()，处理后清零 |
| Holding Registers | 0 | 速度设定值 | 固定测试值 1800 rpm |
| Holding Registers | 1 | 温度上限 | 固定测试值 60 ℃ |
| Input Registers | 0 | 速度反馈 | 固定测试值 2200 rpm |
| Input Registers | 1 | 温度反馈 | 固定测试值 30 ℃ |
| Input Registers | 2 | 设备状态 | 与 Device 同步：0=idle、1=running、2=stopped、3=error |

启动线圈写入成功只表示通信层写入成功。客户端应读回状态寄存器，确认设备是否实际进入 running；例如设备处于 error 时，启动请求不能使其直接恢复运行。

状态寄存器已与 Device 联动；速度、温度及保持寄存器参数仍为固定测试值。当前配套客户端仅通过 Modbus 执行启动控制，停止、复位、故障模拟和速度设置使用文本 TCP。

## 构建与运行

| 依赖 | 要求或用途 |
|---|---|
| C++ | C++17 |
| CMake | 3.16 及以上 |
| Qt Core | 控制台程序、事件循环与定时器 |
| Qt Network | QTcpServer / QTcpSocket |
| Qt SerialBus | QModbusTcpServer |

配套客户端当前使用 Qt 6.11.2。服务端 CMake 配置包含 Qt6 / Qt5 查找分支；具体 Qt 版本及编译器由构建套件决定，不能仅凭该配置认定所有 Qt5/Qt6 版本均已验证。

1. 使用 Qt Creator 打开本仓库的 `CMakeLists.txt`。
2. 选择已安装 Core、Network、SerialBus 模块且编译器匹配的构建套件。
3. 构建并运行 `device_server`，检查控制台监听结果；若端口被占用，先关闭重复运行的服务端。
4. 构建并运行配套客户端，连接本机服务端。
5. 选择文本 TCP 模式执行状态查询、启停和故障模拟，查看客户端回复及服务端输出。
6. 切换到 Modbus TCP 模式，读取寄存器并验证启动线圈与状态读回。

服务端不需要 Widgets 或 Sql 模块；图形界面和 SQLite 报警存储属于配套客户端。

## 延迟回复实验

项目曾通过以下方式验证客户端的异步通信行为：

- 使用 `QTimer::singleShot()` 将命令处理末尾的回复延迟约 2 秒发送。
- 设备操作立即执行，延迟的是回复发送；提前返回的格式错误等回复仍立即发送。
- 延迟回调关联当前连接对象，发送前检查连接状态。

已记录的实验结果包括：等待回复时客户端输入框仍可编辑、修改输入框不影响已提交请求、关闭客户端后服务端继续运行、旧连接的延迟回复不发送到新连接。

这项实验说明定时器和事件循环可以实现异步等待，不要求另外创建线程；在事件回调中休眠或执行耗时计算仍会阻塞对应线程。当前是否保留延迟，以 `main.cpp` 的实际实现为准。

## 已有验证记录

- 客户端连接与断开正常，客户端重启后服务端仍保留设备状态。
- START、STOP、RESET 按状态机规则执行，非法状态下的操作被拒绝。
- GET_STATUS 返回当前状态，速度设置成功后返回设定值。
- 拒绝字段数量错误、非法设备编号、设备不存在、多余参数、非整数速度、越界速度和未知命令。
- 连续错误请求之后仍能正常处理状态查询。
- 配套客户端可读取 Modbus 测试值，并通过启动线圈写入与状态读回完成启动验证。

以上为开发过程中的手工联调记录，未宣称覆盖完整自动化测试。

## 当前限制

- 尚未连接真实设备，不能作为工业现场控制程序直接使用。
- 仅支持 1 号设备；设备状态保存在内存中，服务端重启后恢复 idle。
- 模拟速度、温度及保持寄存器参数尚未与设备运行及文本 TCP 参数设置完整联动。
- Modbus 控制闭环目前仅覆盖启动，其他控制操作通过文本 TCP 完成。
- 客户端的自动重连、状态显示和报警存储不由本服务端实现；Modbus 重连能力需单独完善。
